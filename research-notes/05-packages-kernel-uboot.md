# 05. カーネル・U-Boot・独自パッケージの出自

イメージの「Debian でない部分」はすべて Radxa の APT リポジトリから deb として供給される。
その deb がどこで作られているかを追った結果。

## Radxa APT リポジトリの仕組み

- 配信 URL: `https://radxa-repo.github.io/<suite>`(GitHub Pages)
  - 共通: [`bookworm`](https://radxa-repo.github.io/bookworm/)
  - SoC 別: [`rk3582-bookworm`](https://radxa-repo.github.io/rk3582-bookworm/)(E54C の SoC は RK3582)
  - それぞれに `-test` 版あり(test channel ビルド用)
- リポジトリメタデータは **aptly** で生成(`Release` ファイルに "Generated by aptly")
- 各 `radxa-pkg/*` リポジトリの GitHub Actions が deb をビルド → GitHub Release に添付 →
  `radxa-repo/update-repo-action` が APT リポジトリを更新、という流れ
- `pkgs.json` にリポジトリ内全ソースパッケージのバージョン一覧があり、
  イメージビルド時に `/etc/rsdk/*.pkgs.json` としてスナップショットが保存される

E54C 向けの主要パッケージは**共通リポジトリ(bookworm)側**に入っている
(rk3582-bookworm 側は mesa/libdrm 等のマルチメディア系が中心)。

## カーネル: linux-image-radxa-e54c

```
radxa/kernel (branch: linux-6.1-stan-rkr4.1)   ← Rockchip ベンダーカーネル 6.1 の Radxa フォーク
        │  git submodule "src"
        ▼
radxa-pkg/linux-rk2410                          ← Debian パッケージングリポジトリ
        │  GitHub Actions: devcontainer + QEMU binfmt で `make deb`
        │  (dpkg-buildpackage。テストビルド後に本ビルド)
        ▼
linux-image-6.1.84-N-rk2410_*_arm64.deb         ← カーネル本体
linux-image-radxa-e54c_*_all.deb                ← ボード別メタパッケージ
linux-headers-radxa-e54c / linux-libc-dev-radxa-e54c
        │  radxa-repo/update-repo-action
        ▼
https://radxa-repo.github.io/bookworm (pool/main/l/linux-rk2410/)
```

- 名称の **rk2410** は Rockchip SDK のリリース版(2024-10)を指す社内的な世代名。
  E54C(RK3582 = RK3588S の選別品)は rk2410 世代のカーネルを使う。
- メタパッケージの依存: `linux-image-radxa-e54c` → `radxa-overlays-dkms`(DT オーバーレイ) +
  `linux-image-<ver>-rk2410`
- b2 イメージ搭載: `6.1.84-5`、現在のリポジトリ最新: `6.1.84-8`(2026-08 時点)
- 他ボード向け世代: `linux-rk2312`(6.1.43)、`linux-rk356x`(5.10.160)、`linux-rockchip`(5.10.110)、
  メインライン系 `linux-stable`/`linux-latest` も並存

## U-Boot: u-boot-radxa-e54c

```
radxa/u-boot (branch: next-dev-v2024.10)        ← Rockchip ベンダー U-Boot 2017.09 系の Radxa フォーク
radxa/rkbin                                     ← Rockchip バイナリブロブ (DDR init, BL31, ...)
        │
        ▼
radxa-repo/bsp                                  ← ビルドツール本体(profile: u-boot/rk2410)
        │  fork.conf: BSP_GIT=radxa/u-boot, BSP_BRANCH=next-dev-v2024.10
        │  bsp_radxa-e54c() { bsp_rk3588s; RKBIN_DDR="..._ddr_lp4_1866MHz_lp4x_2112MHz_lp5_2400MHz" }
        │    → RK3582 は rk3588s としてビルド(BL31/DDR blob は rk3588 用を使用)
        ▼
radxa-pkg/u-boot-rk2410                         ← 薄いトリガーリポジトリ(VERSION + pkg.conf のみ)
        │  GitHub Actions: uses radxa-repo/bsp@main (target: u-boot, edition: rk2410)
        ▼
u-boot-rk2410_*_arm64.deb                       ← U-Boot バイナリ(全対応ボード分)
u-boot-radxa-e54c_*_all.deb                     ← ボード別メタパッケージ
                                                   (/usr/lib/u-boot/radxa-e54c/setup.sh を提供)
u-boot-radxa-e54c-spi_*_all.deb                 ← SPI フラッシュ書き込み用
        │  radxa-repo/update-repo-action
        ▼
https://radxa-repo.github.io/bookworm
```

- b2 イメージ搭載: `u-boot-rk2410 2017.09-44` / `u-boot-radxa-e54c 2017.09-44-6b5f314`
- 現在は新世代 `u-boot-rk2601`(radxa/u-boot `next-dev-v2026.01` + rkbin `develop-v2026.01`)からも
  `u-boot-radxa-e54c 2017.09-72` が供給されており、世代移行中
- `image.jsonnet` がこのパッケージの `setup.sh update_bootloader` を呼んでイメージに焼き込む
  (→ [04-image.md](04-image.md))

## task パッケージ・その他の Radxa パッケージ

| パッケージ | ソースリポジトリ | 役割 |
|---|---|---|
| `task-radxa-e54c` | [radxa-pkg/radxa-profiles](https://github.com/radxa-pkg/radxa-profiles) | ボード別設定のメタパッケージ。`radxa-system-config`(システム設定)、`radxa-system-config-kernel-cmdline-ttyfiq0`(シリアルコンソール設定)等を引き込む |
| `rsetup` / `rsetup-config-first-boot` | [radxa-pkg/rsetup](https://github.com/radxa-pkg/rsetup) | Radxa の設定 TUI と初回起動セットアップ |
| `radxa-firmware` | radxa-pkg/radxa-firmware | 無線等の追加ファームウェア |
| `radxa-overlays-dkms` | radxa-pkg/radxa-overlays | デバイスツリーオーバーレイ集 |
| `radxa-bootutils` | radxa-pkg/radxa-bootutils | ブートローダー更新ユーティリティ(`setup.sh` の共通処理) |
| `u-boot-menu` | radxa-pkg/u-boot-menu | `u-boot-update`(extlinux.conf 生成)。Debian 公式版のバックポート |
| `radxa-archive-keyring` | radxa-pkg/radxa-archive-keyring | APT リポジトリ署名鍵 |

## まとめ: 「Debian ソースからどう作られたか」への答え

1. **Debian 部分**: ソースからは作っていない。deb.debian.org の公式 arm64 バイナリを mmdebstrap がそのまま展開
2. **カーネル**: radxa/kernel(Rockchip BSP 6.1 フォーク)を radxa-pkg/linux-rk2410 の CI が deb 化
3. **U-Boot**: radxa/u-boot + rkbin を radxa-repo/bsp が deb 化(RK3582 は rk3588s プロファイル)
4. **統合**: 上記を Radxa APT リポジトリ経由で rsdk(bdebstrap/mmdebstrap)が 1 つの rootfs に合成し、
   guestfish でイメージ化
